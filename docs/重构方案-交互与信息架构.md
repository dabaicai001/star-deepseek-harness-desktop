# 重构方案：StarHub × dsh 交互与信息架构

> 状态：方案稿（只出方案，先不动代码）
> 关联：`docs/dsh主壳融合-任务清单.md`（P2 IPC 桥）、`docs/设计系统.md`
> 目标：解决「链路太长、工具与对话割裂、功能页交互不符合用户操作」三个核心问题。

---

## 0. 现状与问题

当前主壳是 dsh web GUI（chat-first），StarHub 各功能页以同源 iframe 挂在 dsh 壳里。几个可感知的痛点：

| 痛点 | 现状 | 代码位置 |
|---|---|---|
| 导航扁平、DB 分裂 | 侧栏「工具」组平铺 8 条，数据库被拆成 MySQL / Redis / ES 三个独立入口，而 embed 事实表里还有 ClickHouse / PostgreSQL 未露出，两处清单不一致 | `vendor/deepseek-harness/packages/starhub/client-nav/src/client/sections.ts` vs `src/lib/embed.ts`（`EMBED_SECTIONS`） |
| 工具全屏替换对话 | 功能页走 `shell.overlay` 整帧 iframe，打开后完全盖住聊天区，只能二选一 | `vendor/deepseek-harness/packages/starhub/client-nav/src/client/StarHubOverlay.tsx` |
| 连接链路长 | 打开工具 →（无资产）空态 →「去设置添加」→ 返回 → 选资产 → 连接，往返多次 | `src/components/common/EmbedAssetBar.vue`、`src/components/layout/CyberLayout.vue`、`src/lib/embed.ts` |
| 每页结构单薄 | 功能页 = 顶部资产条 + 工作区 + 传输任务条，缺连接状态与一步到位的动作 | `src/components/layout/CyberLayout.vue` |
| AI 不感知工具 | dsh 会话无法知道当前打开的是哪个终端/连接，无法「在终端里问 AI 当前报错」 | P2 待办 |

> 已随本次一起修掉的两个显性问题：SSH `event:listen` ACL 报错（capability 未覆盖远程 `127.0.0.1` origin）、DeepSeek key 被占位 env 锁死（`src-tauri/src/harness/web.rs` / `examples/starhub-web/boot.mjs` 不再注入 `starhub-p0-placeholder`）。

## 1. 目标与设计原则

1. **资产（连接）为中心**：用户先有「一个连接」，再决定对它「做什么」，而非先选「工具类型」再找连接。
2. **对话优先**：工具是对话的延伸，默认与对话共存，而不是全屏替换。
3. **一步到位**：一次点击进入可操作状态，消灭「跳设置 → 返回 → 选资产」的往返。
4. **沿用设计系统**：视觉全部继续走 dsh 现有布局语义（`--dsw-*` token + dsh 布局组件），不引入新的壳范式；`src/styles/cyber.css` 的 token 与 `cyber-*` 组件类**不能提前删**（当前 `.vue` 里仍有 418 处引用），只能随 Vue 应用整体退役（见 `docs/重构方案-B-壳内React插件化.md` P4）时一并移除。

## 2. 信息架构重构（功能入口与导航）

### 2.1 导航分组：工具大类 + 子类

把现在 8 个扁平条目改为「工具」大类下的**子类导航**（形态对齐 dsh 侧栏的 WorkspaceBrowser 分组：大类可展开、子类折叠/展开、每个子类对应一类工具）：

- **工具**（大类，默认展开）
  - **终端**（SSH + SFTP + Broker）
  - **数据库**（合并 MySQL / PostgreSQL / ClickHouse / Redis / ES 为入口，进右侧列表后按类型分组）
  - **Docker**
  - （后续按需加 Excel 等）

- **设置** 和 deepseek harness 中的设置合并（剥离出工具大类）

### 2.2 右侧「工具工作区」列（资产列表 + 实例操作页）

侧栏点**子类** → **右侧工具工作区列**（`workspace` 席位，见 B 路径文档 D1）展示该类的**资产（连接）列表**：

```
[工具]            [右侧工具工作区列]
 ├ 终端           ├ 终端资产列表
 ├ 数据库          │  ├ prod-server (user@host)   ← 点开
 └ Docker         │  ├ test-node
                 │  └ + 新建连接
```

- **点资产行 → 额外弹出该实例的操作页**（复用现有 embed iframe 功能页，功能与之前完全一致——SSH 终端 / 数据库工作台 / Docker 面板；后续随 B 路径逐个壳内 React 化）。
- **右侧交互与现状一致**：资产列表的展示、切换、新建连接入口沿用右侧列的既有语义；无该类型资产时给出「新建连接」空态。
- 这同时取代原「资源/连接」中心（2.2 旧条目）：右侧列就是资源中心，按子类过滤资产。

### 2.3 单一事实表

把 `client-nav/src/client/sections.ts` 与 `src/lib/embed.ts` 的 `EMBED_SECTIONS` 合并为一份（跨端共享的类型 + 清单），消除「导航露 3 个 DB、embed 表里 5 个 DB」的不一致。**本次扩展为「大类 → 子类 → 资产路由」三层**：子类定义分组、图标、段路由前缀、资产类型匹配规则（复用 `routeNameForAsset`），实例路由（带 instanceId）与操作页都在一处派生。

## 3. 功能页内部布局与流程

### 3.1 连接上下文头部（升级 EmbedAssetBar）

现在的资产条只有「图标 + 资产下拉 + 切换」，升级为「连接上下文头部」：

- 资产名 + 类型徽标
- 连接状态：未连接 / 连接中 / 已连接 / 错误（配状态色）
- 动作：一键连接 / 断开、切换资产、**内联新建连接**（不再跳到设置）
- 保留 `postEmbedOpenSection` 的跨壳切段能力（无资产时提供「去资源中心」）

### 3.2 统一状态机

每个功能页统一为同一套状态流转，减少页面间行为差异：

```
空态 → 连接中 → 已连接（主工作区） → 断开 / 错误
```

- 空态页（`EmbedSectionEmpty`）直接内联「新建连接」表单，而不是只给「去设置」按钮。
- 已连接后隐藏头部里的表单，只保留状态与动作。

### 3.3 打开即用

`resolveEmbedTarget` 现在只挑「最近使用资产」但还要用户再点连接。改为：打开工具即自动连接最近资产；若该类型没有资产，直接落在内联新建连接的空态。

## 4. dsh 对话区 ↔ StarHub 工具区融合

### 4.1 从 overlay 到 docked workspace

现状工具走 `shell.overlay` 整帧覆盖。目标是把工具「停靠」进 dsh 已有三栏布局的右栏（或新增 workspace 席位），让聊天区保持可见，实现「左聊右做」。

### 4.2 席位选型（推荐 C）

dsh `ui-layout` 现有顶层席位（`packages/client/ui-layout/src/client/index.ts`）：

- `sidebar`：左栏（single，被 SidebarRoot 占用，内含 `sidebar.navigation` 等内席）
- `conversation`：中栏（single，被 ConversationRoot 占用，内含 `conversation.view` 页签、composer、input 内席）
- `details`：右栏（single，被 DetailsPanel 占用，内含 `tool-details` 内席）
- `shell.overlay`：浮动层（list，当前 StarHub 工具用的就是它）

三个候选：

| 方案 | 形态 | 优点 | 代价 |
|---|---|---|---|
| A. `conversation.view` 页签 | 工具作为聊天区的一个 tab | 改动小（P0 已验证过） | 仍是「聊天 ↔ 工具」二选一，不满足边聊边做 |
| B. `shell.overlay` 半屏/可调宽 | 覆盖层改为右侧可拖宽抽屉 | 改动中等 | 覆盖层本质仍浮在对话之上，交互割裂感残存 |
| **C. `details` 右栏 tool-details（推荐）** | 工具停靠右栏，聊天居中 | 原生三栏布局、边聊边做、可拖宽 | 需要与 DetailsPanel / `tool-details` 席位对齐，改动较大 |

推荐 C：利用 dsh 已有的 `details` 右栏语义，把 StarHub 工具 iframe 注册到 `tool-details` 内席（或与 DetailsPanel 协商一个「工具工作区」内席），保留「最大化」按钮可临时全屏。

### 4.3 AI 上下文绑定（对应 P2 待办）

把「当前工具 + 资产/连接 id + 关键状态」同步给 dsh 会话，支撑：

- 在终端里选中报错 → 让 AI 解释
- 在数据库结果上让 AI 生成查询 / 分析
- AI 主动建议打开某个工具并带着目标资产

> **实施状态(2026-08-15)**:已全部落地——
> 1. **客户端半边**:client-nav 壳级 store 持有当前工具状态(`activeSubcategory` / `activeAssetId`),iframe 视图经 `starhub-embed-conn-state` / `starhub-embed-conn-action` 协议上报/接收连接状态(方案 3.1 的状态桥)。
> 2. **host 侧注入**:新增 dsh host 插件 `@deepseek-ai/dsh-starhub-tool-context`(仿 `time-context` 的 `agent/pre-step`),读取 `starhub-tool-context` settings namespace,把「当前工具 + 资产 + 路由前缀」作为 plugin 来源 user message 注入每个 agent 请求;client-nav 在子类/资产变化时经 `api.settings.update` 写入该 namespace。已注册进 starhub-web 组合。

## 5. 分阶段实施

| 阶段 | 内容 | 风险 | 主要改动面 |
|---|---|---|---|
| P1 | 工具大类 + 子类导航、右侧工具工作区列（子类资产列表）、实例操作页（复用 embed iframe）、单一事实表（三层） | 中 | `client-nav`（大类/子类/资产列表/操作页）、`packages/client/ui-layout`（workspace 席位）、`src/lib/embed.ts`、资产列表组件 |

## 6. 不做的事

- 不改动 dsh 核心会话 / 模型 / 凭据层（key 输入已由 dsh onboarding / Models 页承接）。
- 不做全新独立外壳（继续 chat-first 主壳）。
- 不恢复已退役的多窗口 / tab 拖出（`windowDetach`）。
