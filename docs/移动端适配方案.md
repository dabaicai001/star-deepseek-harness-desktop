# StarHub 移动端适配方案

> 版本:v1.0(2026-07-17,随 v0.32 规划)
> 状态:**方案评审中,未实施**
> 范围:iOS / Android / 小屏浏览器。目标是在手机上完成"应急查看 + 轻量操作",
> 而不是把桌面端 280+ 功能完整搬进 6 寸屏。

---

## 1. 现状盘点:桌面优先架构的移动端障碍

| 层 | 桌面端现状 | 移动端障碍 |
|---|---|---|
| 桌面壳 | Tauri 2(Windows/macOS/Linux) | Tauri 2.x 已支持 iOS/Android,但需单独工程配置与签名体系 |
| 数据库代理 | **Go sidecar**(stdio JSON-RPC 子进程) | ❌ iOS 禁止 fork 子进程;Android 可打包 Unix 可执行文件但审核与兼容性风险高。**最大单点障碍** |
| SSH/SFTP | Rust `russh` / `russh-sftp`(主进程内) | ✅ Rust 可交叉编译到 iOS/Android(静态库) |
| 终端 | xterm.js 5 | ⚠️ 可用,但虚拟键盘、IME、触控选择、快捷键全部要重做 |
| 结果网格 | Univer Sheets(Canvas) | ⚠️ 重,低端机掉帧;触控手势需额外适配 |
| 布局 | 260px sidebar + 40px menubar + 30px statusbar,1280×800 起步 | ❌ 手机竖屏 ~390px 宽,信息架构不成立 |
| 输入 | 键盘 + 鼠标(右键菜单、拖拽、悬停 tooltip) | ❌ 无 hover、无右键、触控目标需 ≥44px |
| 窗口系统 | 多窗口 / 标签页拖出(v0.33+) | ❌ 移动端单窗口全屏 |

**结论**:不能直接"编译到手机上跑"。需要一条分阶段的路线,先 Web 响应式,再原生壳。

---

## 2. 目标与原则

1. **场景定位**:运维应急 — 看监控、查日志、跑预置命令、重启服务;不是完整替代桌面端。
2. **只读优先**:第一版以"看"为主(连接状态、仪表盘、终端输出、查询结果),高危操作(删库、rm、批量广播)默认不下放。
3. **复用最大化**:Vue 组件、Pinia store、设计系统 token 全部复用;新增的只有布局壳与交互层。
4. **不破坏桌面端**:所有适配以"追加断点与替换壳"方式进行,桌面布局零回归。

---

## 3. 路线对比

| 方案 | 说明 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 响应式 Web(PWA)** | 同一套 Vue 前端部署为 Web 应用,后端换成"StarHub Server"(把 src-tauri 的 Rust 核心抽成 headless 服务),手机浏览器访问 | 无商店审核、即开即用、一套代码 | 需要一台常开服务器;密钥/会话安全模型重做;Web 端无系统 keyring | **P0 先做** — 成本最低,验证移动端交互 |
| **B. Tauri Mobile** | `tauri android/ios` 原生壳,Rust 核心编为静态库内嵌 | 复用 Rust 核心;本地直连 SSH,无需中转服务器 | Go sidecar 必须替换;iOS 后台长连接被系统杀;包体积与签名维护成本 | **P1 主攻方向** |
| **C. 原生 App(Swift/Kotlin)+ Web 内容层** | 原生壳内嵌 WebView 跑同一前端 | 原生体验最好(推送、生物识别) | 两套壳代码,维护翻倍 | 不推荐,除非 B 走不通 |

**推荐路线:A(P0)→ B(P1)**,C 作为兜底。

## 4. 关键技术决策

### 4.1 Go sidecar 怎么办?(方案 B 的核心问题)

| 选项 | 说明 | 评估 |
|---|---|---|
| **B1. Rust 原生驱动替换** | 把 DB 访问下沉到 Rust:`sqlx`(MySQL/PG/SQLite)、`redis-rs`、`clickhouse-rs` 等,废弃 sidecar | 工作量大但一劳永逸;iOS/Android 都能跑;还能省掉 stdio RPC 开销。**推荐,分库逐步替换** |
| B2. sidecar 编为 Android 可执行文件 | `GOOS=android` 编译,App 内 exec | 仅 Android 可行,iOS 无解,pass |
| B3. 远程 agent | 手机连桌面端/服务器上的 sidecar | 依赖在线中转,违背"本地直连"价值,仅作补充 |

迁移顺序建议:SQLite → PostgreSQL → MySQL → Redis → ClickHouse(按 sqlx 覆盖度与内部使用量排)。

### 4.2 布局系统:断点与壳替换

新增三个断点(追加进 `cyber.css`,不动桌面现有样式):

| 断点 | 宽度 | 布局 |
|---|---|---|
| `desktop` | ≥1024px | 现有布局(titlebar + menubar + sidebar + statusbar) |
| `tablet` | 768–1023px | sidebar 默认折叠(60px),tab 条保留,右面板改抽屉 |
| `phone` | <768px | **换壳**:底部 TabBar(首页/终端/文件/AI/我的)+ 顶部精简栏(连接名 + 状态点 + 返回) |

phone 壳的信息架构:

```
┌─────────────────────┐
│ ‹ 资产名      ●  ⋮  │  44px 精简顶栏(返回 / 状态 / 更多)
├─────────────────────┤
│                     │
│    workspace        │  全屏单工作区,左右滑切 tab
│    (router-view)    │
│                     │
├─────────────────────┤
│ 🏠   🖥   📁   🤖   ⚙ │  56px 底部 TabBar + 安全区
└─────────────────────┘
```

实现要点:
- 新建 `src/components/layout/MobileLayout.vue`,与 `CyberLayout` 平级;`App.vue` 按 `matchMedia('(max-width: 767px)')` + UA 选择壳。
- 路由层不动(同一套 `/ssh/:id`、`/db/...`);Mobile 壳内只允许一个活动 tab,tab 切换走底部栏 + 左右滑动手势。
- 触控目标:所有 `.action-btn` / `.tb-btn` 在 phone 断点下 min-height/min-width 提到 40–44px(`@media (max-width: 767px)` 追加,不改桌面值)。
- `safe-area-inset-*`:底部 TabBar、TransferDock、弹窗都要 `env(safe-area-inset-bottom)` 适配刘海/Home 指示条。
- 右键菜单 → 长按弹出同一 `ContextMenu`(组件已支持坐标定位,补一个 `longpress` 指令即可)。
- 悬停 tooltip(`data-tooltip`)在触控下不展示,关键信息改常驻文本。

### 4.3 SSH 终端(移动端最难的交互)

1. **虚拟键盘**:xterm.js 在移动端点击只弹系统键盘,需要:
   - 终端上方加一条 **快捷键盘条**(Esc / Tab / Ctrl / ↑↓←→ / `|` `/` `~` `-` / 粘贴),横滑扩展;
   - Ctrl 做成"粘滞键"(按一下高亮,下一个键带 Ctrl);
   - IME:中文输入沿用桌面端 10.1 节的 keydown 方案,移动端搜狗/讯飞需真机回归。
2. **触控选择/滚动**:双指捏合调字号(复用 `themeStore.fontSize`);三指下滑复制选中;滚动惯性由 xterm 的 `scrollOnUserInput` 配置兜住。
3. **ZMODEM 不可用**:移动端没有本地文件系统概念暴露给 WebView,`rz/sz` 降级为提示"请在桌面端使用",SFTP 面板承接文件传输。
4. **分屏/广播**:竖屏禁用 split,入口隐藏。

### 4.4 SFTP / 传输

- 三栏布局 → 单栏:面包屑 + 文件列表;本地面板取消(手机端文件走系统分享/Document Picker)。
- 上传:`<input type=file>` + 系统分享面板接收(`Share Target`,PWA 下用 Web Share Target API)。
- 下载:落地到 App 文档目录,系统"用其他应用打开"导出。
- 传输任务栏(v0.32 的 TransferDock)在 phone 断点下改为底部全宽卡片,收起态缩成底部 TabBar 上的进度角标。

### 4.5 数据库 / 仪表盘

- 查询结果:Univer 在 phone 断点下替换为**轻量只读表格**(虚拟滚动 div 表格),编辑能力回桌面端;SQL 编辑器保留 CodeMirror 6(移动端支持尚可)。
- 仪表盘:ECharts 改单列堆叠,钻取弹层全屏化。
- AI 助手:对话式天然适配手机,优先级反而最高;输入框常驻底部,复用移动端键盘方案。

### 4.6 安全

- 凭据:iOS Keychain / Android Keystore,`keyring-rs` 已支持双平台,代码零改动,仅需 capabilities 声明。
- 方案 A(Web)下:HTTPS + WebAuthn/设备码登录,禁止在 localStorage 存明文 token(用 httpOnly cookie)。
- 锁屏:App 进入后台 30s 后回前台要求生物识别解锁(`LocalAuthentication` 插件或原生层实现)。

## 5. 里程碑

| 阶段 | 内容 | 交付物 | 预估 |
|---|---|---|---|
| **P0 响应式 Web** | tablet/phone 断点、MobileLayout 壳、触控目标、长按菜单、安全区;Rust 核心抽 headless server(仅 SSH + 仪表盘) | 手机浏览器可用:连接列表、终端(只读+快捷条)、仪表盘 | 3–4 周 |
| **P1 Tauri Mobile(Android 先行)** | Rust 静态库化、sidecar → Rust 驱动(SQLite/PG/MySQL)、SFTP 单栏、生物识别锁屏、Android 商店包 | Android APK/AAB 内测 | 6–8 周 |
| **P2 iOS + 体验完善** | iOS 签名与后台保活(VOIP/BGTask 不可行 → 接受断连+快速重连)、Share Target、推送(Webhook 告警 → APNs)、全量 DB 驱动 | iOS TestFlight | 4–6 周 |

明确**不做**:手机端 Excel/Univer 编辑、命令广播多窗格、多窗口、桌面端功能全量对齐。

## 6. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| iOS 禁止子进程,Go sidecar 无法运行 | 移动端无 DB 能力 | 4.1 节 B1:Rust 原生驱动替换(P1 核心工作) |
| iOS 后台 30s 杀长连接 | SSH 断连 | 前台态保持 + 断线自动重连(已有 autoReconnect)+ 会话恢复提示 |
| xterm.js 触控体验天花板 | 终端难用 | 快捷键盘条 + 手势;极端场景引导回桌面端 |
| 方案 A 需常开服务器 | 部署成本 | 定位"团队可选组件",单机二进制 + docker-compose 一键起 |
| 双壳(MobileLayout/CyberLayout)长期分叉 | 维护成本 | 壳只负责布局,业务组件 100% 复用;UI 回归跑双套断点 |

---

## 7. 验收标准(P0)

1. iPhone 14 Pro / Pixel 8 真机竖屏:连接 SSH 成功,终端可输入命令(含中文),快捷键条可用。
2. 所有可点元素触控目标 ≥40px,无 hover 依赖的功能缺失。
3. 仪表盘图表单列展示,可钻取。
4. 桌面端 1280×800 回归零差异(断点只追加不修改)。
